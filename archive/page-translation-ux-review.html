Phase 3.1 UX Review

全文翻譯段落呈現與同步選取建議

這份 review 聚焦在兩件事：翻譯後段落如何更像閱讀工具而不是插入訊息，以及使用者選取原文時，如何讓對應譯文同步被看見、定位或複製。

段落呈現 同步選取 實作建議 Phase 規劃

結論

建議採用
先做「雙語段落卡 + 配對高亮」，不要一開始做真正的雙區文字選取。

Chrome/Edge 的 Selection API 對同時選兩段不同 DOM 文字支援有限。比較穩的做法是：使用者選取原文時，視覺上同步高亮對應譯文，並提供「複製譯文」「複製雙語」「定位原文」按鈕。

P1 翻譯卡更像閱讀註解

譯文用淡綠底、左側語言色條、緊湊標籤與操作鈕，避免整頁被一堆大塊卡片切碎。

P1 原文/譯文配對高亮

每個原文段落和譯文段落綁定同一個 data-ffb-pair-id。選到原文時，譯文卡同步亮起。

P2 複製體驗補強

提供「複製譯文」「複製雙語」「只看譯文」操作，比強行同步真實選取更可靠。

段落呈現可以怎麼美化

目前問題 譯文區塊容易像一般提示訊息，段落多時視覺節奏會碎；語言、狀態、操作也不夠明確。
建議方向 把譯文做成「輕量閱讀註解」：低彩度背景、左側色條、語言 label、短操作鈕，並維持原文主視覺權重。
不要做 不要每段都放很厚的 card shadow，也不要把譯文字級做得比原文大；長文頁面會變成工具 UI 搶過內容。

建議版型

Large language models can summarize, translate, and restructure long passages, but readers still need clear context while moving through the original page.

繁體中文 · Llama 4 Scout

大型語言模型可以摘要、翻譯並重整長段文字，但讀者在瀏覽原始頁面時，仍然需要清楚的上下文。

A good reading tool should preserve the page flow while making translated content easy to scan and compare.

繁體中文 · Llama 4 Scout

好的閱讀工具應該保留原頁面的閱讀流，同時讓譯文容易掃讀與比較。

推薦細節

  • 譯文卡左側保留 3px 綠色線，建立「這是翻翻吧翻譯」的固定識別。
  • 語言與模型放在小 label，不干擾閱讀，但可追溯輸出來源。
  • 操作鈕只在 hover 或 selected 狀態顯示完整，平常降低存在感。
  • 當原文被選到或 hover 時，譯文卡用淡色外框同步亮起。
  • 長譯文可折疊成 4 行，避免單段過長把頁面撐太開。

原文與譯文同步選取

重點判斷
同步「視覺選取」可做且穩；同步「真正文字反白選取」不建議作為第一版。

使用者拖選原文時，瀏覽器通常只維持一個真實 selection range。若強制把 selection 切到譯文，會讓使用者正在選的原文消失，體感反而怪。

實作建議

1. 建 pair id

翻譯時為原文與譯文卡加入同一個 data-ffb-pair-id。

2. 監聽 selection

用 document.selectionchange 找目前 selection 所在的原文或譯文。

3. 同步高亮

清除上一組高亮，為對應 pair 加上 ffb-pair-active。

4. 顯示操作

在 active 譯文卡顯示複製譯文、複製雙語、定位原文。

資料結構

原文段落 class="ffb-page-source-translated"、data-ffb-pair-id="ffb-pair-12"
譯文卡 class="ffb-page-translation-block"、data-ffb-pair-id="ffb-pair-12"
active 樣式 ffb-pair-active 套在原文與譯文卡，用淡藍原文、淡綠譯文呈現同步。
clipboard 在 state 裡保存 sourceText 與 translatedText，提供複製譯文與複製雙語。

互動規則

  • 使用者選取原文任一文字：整個原文段落和對應譯文卡同步高亮。
  • 使用者選取譯文：對應原文段落同步高亮。
  • 點譯文卡：不強迫改變瀏覽器選取，只讓 pair active，避免干擾閱讀。
  • 按 Esc 或點空白處：取消 pair active。
  • 切換只看譯文模式時，pair highlighter 仍可保留，但「定位原文」會先切回雙語或原文可見。
