軟體工程師視角

議題 目前觀察 建議 優先級
模型 registry background.js、popup.js、options.js、state.js 各自維護模型資料。 建立單一 models.js 或 model-registry.json，統一 id、label、provider、fallback、migration。 高
快取 key 目前以 action:text 為主，換模型或語言後可能回舊結果。 改成 model:targetLang:action:textHash:contextHash。 高
錯誤可觀測性 使用者看到 API 錯誤時，很難知道是 key、額度、provider、或網路問題。 錯誤分類：key invalid、quota、provider down、timeout、fallback used。設定頁測試連線也顯示原因。 高
全文翻譯架構 尚未有 DOM 分段、排程、翻譯狀態管理。 先做可見區段翻譯，不直接全頁掃描；使用 IntersectionObserver + batch queue。 中
設定資料版本 已有模型 migration，但之後設定會更多。 加入 settingsVersion，集中處理 migration。 中

UI/UX 設計視角

常駐右側懸浮球

建議優先做。選字工具列很好用，但新使用者需要一個穩定入口知道「翻翻吧正在這裡」。

  • 吸附右側，可拖曳。
  • 可暫停此網站。
  • 可開啟最近查詢、全文翻譯、設定。
  • 每個網站記住開關狀態與位置。

語言設定

應該從隱性 prompt 變成清楚控制。這會比多加模型更有使用者體感。

  • 翻譯成：跟隨瀏覽器 / 繁中 / 簡中 / 英文 / 日文 / 韓文。
  • 解釋語言：繁中 / 英文 / 跟隨目標語言。
  • TTS 語音：自動 / 指定語言。

全文翻譯入口

不要一開始就自動翻全頁，應該由懸浮球觸發，並提供明確狀態。

  • 翻譯目前可見內容。
  • 顯示進度與停止按鈕。
  • 原文 / 譯文 / 雙語切換。
  • 保留頁面可讀性，不改壞表單與按鈕。

Phase 2A：穩定性整理與模型基礎建設

目標 讓模型、fallback、設定 migration、快取與錯誤處理變成可維護基礎，避免之後新增語言/全文翻譯時到處改檔。
功能內容
  • 新增集中式模型 registry：provider、model id、顯示名稱、badge、API key 類型、fallback model。
  • 集中處理舊模型 migration，取代散落在 background.js、popup.js、options.js 的重複 map。
  • 快取 key 加入 model、target language、action、text hash、context hash。
  • OpenRouter provider error 顯示成易懂訊息，例如「DeepSeek 免費節點忙碌，已改用備援模型」。
  • 設定頁測試連線列出主模型與備援模型結果。
主要檔案 models.js、background.js、popup.js、options.js、content/state.js、測試檔。
驗收標準 切換 Groq / Gemini / OpenRouter 都能成功；舊模型設定會自動遷移；fallback 可被測試；快取不會跨模型或語言誤用。

Phase 2B：右側常駐懸浮球與快速入口

目標 讓使用者不必先選字也能知道翻翻吧存在，並提供穩定入口給最近查詢、設定、暫停網站與全文翻譯 Beta。
功能內容
  • 新增右側吸附懸浮球，預設貼在頁面右側中段，不擋主要閱讀內容。
  • 支援拖曳與吸附，並用 chrome.storage.local 記住每個網站的位置。
  • 點擊後展開迷你選單：翻譯可見內容、最近查詢、暫停此網站、開啟設定。
  • 提供「本網站停用」與「全部網站停用」狀態。
  • 在輸入框、影片全螢幕、特殊互動頁降低干擾：自動縮小或暫停顯示。
主要檔案 content/floating-ball.js、content/main.js、content.css、manifest.json、設定頁。
驗收標準 一般網頁、Google Docs 類複雜頁、YouTube/影片頁不明顯干擾；重新整理後位置與停用狀態保留；鍵盤與滑鼠都可使用。

Phase 2C：常見語言支持與輸出偏好

目標 讓使用者能控制翻譯、解釋與朗讀語言，避免所有輸出都隱性固定成繁中。
功能內容
  • 新增目標語言設定：跟隨瀏覽器、繁中、簡中、英文、日文、韓文、德文、法文、西文、葡文。
  • 新增解釋語言設定：跟隨目標語言、繁中、英文。
  • Prompt 依設定輸出，單字 JSON 增加來源語言與目標語言欄位。
  • TTS 語音跟隨字典偵測語言；瀏覽器 fallback 不再固定 en-US。
  • 結果卡顯示目前語言與模型，讓使用者知道輸出規則。
主要檔案 options.html、options.js、background.js、content/result-card.js、content/state.js。
驗收標準 相同英文段落可分別輸出繁中、日文、英文解釋；TTS 對英文、日文、韓文能選到合理語音；設定改變後快取不串用。

Phase 3：網站全文翻譯 Beta

目標 提供文章閱讀場景的可見段落翻譯，不做高風險的整頁即時替換，先確保可控、可停止、可還原。
功能內容
  • 從懸浮球進入「翻譯目前可見內容」。
  • 用 IntersectionObserver 收集可見段落，排除按鈕、表單、導覽、程式碼、廣告區。
  • 分批翻譯，每批限制字數與 request 數，避免爆 token 或觸發 rate limit。
  • 提供原文、譯文、雙語模式與停止按鈕。
  • 每個段落保留原 DOM，使用旁插譯文區塊，避免破壞頁面互動。
  • 加入成本/額度保護：超過字數時先詢問，或只翻可見區。
主要檔案 content/page-translator.js、content/floating-ball.js、background.js、content.css。
驗收標準 長文章可分批翻譯且能停止；頁面 reload 後不留下殘留 DOM；表單、按鈕、程式碼區不被翻壞；遇到 API error 可重試單一段落。
