核心原則

建議 本地資料是主資料庫

單字收藏、查重、更新、已收藏狀態、頁面高亮、刪除，都放在 Chrome local storage 管理。

這讓 extension 可以快速判斷某個字是否已存，不需要讀 Obsidian 檔案。

整合 Obsidian 是沉澱出口

收藏時可自動 append 到 Obsidian，也能手動匯出今日新增。

Obsidian 筆記是可讀、可搜尋、可長期保存的外部知識庫。

暫緩 不做雙向同步

第一版不從 Obsidian 反向讀回 extension。

避免 Markdown 解析、刪除衝突、重新命名、跨裝置同步等複雜問題提早爆開。

Review point A：這個邊界是否 OK？

Extension 本地資料負責互動狀態；Obsidian 負責筆記輸出與沉澱。第一版只做 one-way export。

Decision：OK，依此邊界實作。

本地資料模型

建議新增 storage key：fanFanBaVocabularyItems，第一版儲存在 chrome.storage.local。這是 Chrome extension 的本地持久化儲存，關掉瀏覽器不會消失；除非使用者移除 extension、清除擴充功能資料，或在單字本內手動刪除。

資料量初期不大，第一版用 keyed object map 讓查重快速；同時保留未來遷移到 IndexedDB 的空間，避免單字量變大後被單一 JSON 物件拖慢。

欄位 用途 第一版是否必做
id 建議用 lang:normalizedWord，同字同語言去重。 必做
sources 保留來源頁面與語境，讓單字不是孤立資料。 必做，但最多保留近 5 筆即可
count / lastSeenAt 支援「最近遇到」「最常遇到」視圖。 必做
status 先放 learning / known，未來可接輕量複習。 可做

Review point B：同字去重規則

建議第一版用「來源語言 + 小寫/trim 後的單字」去重。例如 en:infrastructure。片語也照同規則處理。

Decision：OK；補充擴充性要求：使用 object map、限制來源筆數，未來可 migration 到 IndexedDB。

建議 Markdown 格式

## 2026-05-26

### infrastructure

- 詞性：n.
- 音標：/ˈɪnfrəˌstrʌktʃər/
- 涵義：基礎建設；基礎設施
- 解釋：支撐社會、城市或系統運作的基本設施。
- 用法：常用於交通、能源、網路、公共建設等脈絡。
- 近義詞：facilities
  - 差異：facilities 偏具體設施，infrastructure 偏整體支撐系統。
- 例句：
  - The city invested in public infrastructure.
  - 這座城市投資公共基礎建設。
- 來源：[Article Title](https://example.com/article)
- Tags：#翻翻吧 #vocab/en
推薦策略： 收藏第一次 append 完整單字卡；之後再遇到同字，只更新 extension 本地的 count 與 lastSeenAt。 若使用者開啟「記錄每次出現來源」，再 append 一行來源紀錄到 Obsidian。
Review point C：Obsidian 是否要預設自動匯出？

建議預設開啟，但前提是使用者已設定 Vault。沒有設定時只收藏到本地，並提供「稍後匯出」。

Decision：OK。收藏到本地指 chrome.storage.local，關掉瀏覽器不會消失。

使用流程

Flow 1 從字典卡收藏

  1. 使用者選字並按翻譯。
  2. 字典卡顯示收藏按鈕。
  3. 按下收藏後，本地寫入單字本。
  4. 若已設定 Obsidian，自動 append。
  5. 按鈕變成已收藏狀態。

Flow 2 今日新增

  1. 懸浮球選單進入單字本。
  2. 預設顯示今日新增。
  3. 可搜尋、複製、刪除、手動匯出。
  4. 可切到全部 / 最近遇到 / 最常遇到。

Flow 3 已收藏高亮

  1. 頁面載入後讀本地單字本。
  2. 只在文章主內容或可見區域做淡標記。
  3. Hover 顯示簡短釋義。
  4. 設定可關閉，避免干擾閱讀。
高亮要非常克制： 第一版不要全文 DOM 大掃描，也不要在每個網站都強制開啟。建議使用可見區域、節流、上限數量，並預設只在使用者開啟「單字高亮」後生效。
