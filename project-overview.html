現況

產品定位

選取網頁文字後提供翻譯、解釋、優化改寫，也提供右側常駐浮球作為全文翻譯、最近查詢、單字本、暫停網站與設定入口。

主要 Provider

模型 registry 集中在 models.js，支援 Groq、Gemini、OpenRouter。預設模型為 Groq 的 Llama 4 Scout。

目前重點

目前版本線是 v1.6.x：設定備份 / 還原、API Key local storage、Obsidian 精準路徑、request abort、responsive 與 a11y hardening 已完成；下一步建議進 v1.6.3 實站 QA。

最新進展

2026-06-02 已把舊 Phase 編碼對齊版本里程碑，並整合散落 review / roadmap / session context 到本文件。Jest 仍因 Windows / OneDrive 權限 EPERM 阻塞，依指示暫不修環境。

架構流程

選字工具流程

  1. content/main.js 偵測 selection。
  2. content/toolbar.js 顯示翻譯/解釋/優化工具列。
  3. content/main.js 透過 message 或 port 呼叫 background.js。
  4. background.js 依模型 provider 呼叫 Groq/Gemini/OpenRouter。
  5. content/result-card.js 顯示字典卡、段落結果、Obsidian 與收藏操作。

浮球與全文翻譯流程

  1. content/floating-ball.js 建立右側吸附浮球。
  2. 浮球可開收藏/紀錄、全文翻譯、設定，並提供「在此網站停用」。
  3. content/page-translator.js 收集可見段落並逐段翻譯。
  4. 全文翻譯請求帶 pageTranslation: true，短標題不走單字字典 prompt。
  5. 可見段落收集會避開已翻譯元素、父子節點重複與相同文字重複。
  6. 翻譯狀態面板提供雙語/譯文/原文與密度切換。
  7. 全文模型由設定頁 pageTranslationModel 管理。

設定頁整合方案

已採用方向：優先使用「方案 A：分頁式設定中心」。它能把單欄長表單收斂成可掃描的設定中心，同時對現有 options.js 與 storage 邏輯影響最小。

方案 A：分頁式設定中心

  • 左側分組：模型與金鑰、語言與朗讀、Obsidian、隱私與說明。
  • 使用者只看當下要改的區塊，API Key 集中在「模型與金鑰」。
  • 推薦給正式版：主要是 HTML / CSS 結構調整，開發量低、可維護性高。

方案 B：初次設定精靈

  • 流程化：選 AI 供應商、輸入 API Key、設定語言與朗讀、接 Obsidian。
  • 適合 onboarding 或首次安裝導引。
  • 若目標是快速修設定頁過長，先不作為第一優先。

方案 C：總覽儀表板

  • 首頁顯示設定健康度與常用偏好；少改的 API Key、安全說明、Obsidian 細節放可展開區塊。
  • 適合已設定完成的使用者，日常打開時先看「是否正常」。
  • 可作為方案 A 穩定後的進一步優化。

決策紀錄

產品與工程方向

  • 同意先做模型 registry、設定 migration、快取 key 改良與 provider fallback，再擴充更多產品功能。
  • 同意右側常駐浮球作為穩定入口，承接最近查詢、單字本、全文翻譯、暫停網站與設定。
  • 同意語言偏好從隱性 prompt 變成明確設定，包含目標語言、解釋語言與 TTS 語音模式。
  • 全文翻譯先做可見段落 Beta，不直接做完整全頁替換，避免成本、效能與 DOM 相容性風險。

近期重要決策

  • API Key 存在 chrome.storage.local，不跟 Chrome 帳號同步；設定備份預設不含 API Key。
  • 設定匯出 / 匯入先用本機 JSON；Google Drive appData 同步排入 v1.7.0，API Key 上雲前必須先設計加密。
  • Obsidian 單字匯出完全依照使用者填寫資料夾，不再自動追加 /單字本。
  • Roadmap 以版本里程碑為主，不再使用舊文件裡的 Phase 2A / 2B / 2C / Phase 3 / P1 作為目前主線編碼。

全文翻譯 UX

建議路線：先做好雙語段落卡、pair id 與視覺同步高亮；不要第一版就嘗試真正雙區文字反白，因為 Chromium Selection API 對 multiple ranges 支援不可靠。

段落呈現

  • 譯文卡像輕量閱讀註解：淡綠底、左側品牌色線、小型語言 / 模型 label。
  • 降低 shadow 與大卡片感，避免長文頁被工具 UI 切碎。
  • 長譯文可折疊，並用密度設定控制頁面節奏。

同步互動

  • 原文段落與譯文卡綁定相同 data-ffb-pair-id。
  • 使用者選取或 hover 原文時，對應譯文卡加上 active 樣式；反向選譯文也同步高亮原文。
  • 點譯文卡只設定 pair active，不強制改變瀏覽器原生 selection。

操作補強

  • 複製譯文、複製雙語、定位原文、重試此段排入 v1.8.0+。
  • 定位原文在只看譯文模式下需先切回雙語或原文可見。
  • Esc 或點空白處取消 pair active。
