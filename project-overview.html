Google Cloud 設定手順

明天接著做這段：Edge / Chromium 的 identity.launchWebAuthFlow fallback 要用 網頁應用程式（Web application）OAuth 用戶端 ID，不要沿用 Chrome native auth 的 Chrome 擴充功能 client。中文 Google Cloud 介面路徑是 Google Auth Platform > 用戶端，網頁應用程式需要在 已授權的重新導向 URI 加入 extension redirect URL。

0. 先從 Edge 複製 Redirect URL

  1. 打開 Edge，進入 edge://extensions。
  2. 確認翻翻吧已重新載入，然後開翻翻吧 Options / 設定頁。
  3. 切到「雲端同步」分頁。
  4. 從狀態列找到 Redirect URL：https://xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.chromiumapp.org/。
  5. 貼到 Google Cloud 時只能貼純 URL：https://xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.chromiumapp.org/。不要貼到 Redirect URL： 這段文字，也不要有前後空白或換行。
  6. 這串要完整複製，包含最後的 /；如果 Edge extension ID 之後改變，Redirect URL 也要重新加入 Google Cloud。

1. 建立 / 選用網頁應用程式 OAuth 用戶端

  1. 打開 Google Cloud 控制台：Google Auth Platform > 用戶端。
  2. 確認上方 project 是翻翻吧目前使用的同一個 Google Cloud project。
  3. 如果 Google 要求先設定 Google Auth Platform，點「開始使用」（Get Started）。
  4. 在「品牌宣傳」（Branding）填「應用程式名稱」（App name）：翻翻吧 或 Fan Fan Ba；「使用者支援電子郵件」與「開發人員聯絡資訊」填你的信箱。
  5. 在「目標對象」（Audience）選「外部」（External）；如果「發布狀態」是「測試中」（Testing），把 TeaKingdom@gmail.com 加進「測試使用者」（Test users）。
  6. 回到 Google Auth Platform > 用戶端，點「建立用戶端」（Create Client）。
  7. 「應用程式類型」（Application type）選 網頁應用程式（Web application）。
  8. 「名稱」（Name）建議填 Fan Fan Ba Edge Web Auth。
  9. 「已授權的 JavaScript 來源」（Authorized JavaScript origins）留空。
  10. 「已授權的重新導向 URI」（Authorized redirect URIs）點「新增 URI」（Add URI），只貼上第 0 步的純 URL，例如 https://xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.chromiumapp.org/。
  11. 點「建立」（Create），建立後複製「用戶端 ID」（Client ID）；格式會像 1234567890-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.apps.googleusercontent.com。
  12. 不要把「用戶端密碼」（Client secret）放進 extension；翻翻吧 Web Auth fallback 只需要「用戶端 ID」。

2. 填回翻翻吧設定頁

  1. 回到 Edge 的翻翻吧 Options / 設定頁。
  2. 切到「雲端同步」分頁。
  3. 把網頁應用程式 OAuth「用戶端 ID」（Client ID）貼到「Edge / Chromium Web Auth Client ID」欄位。
  4. 點「儲存 Web Auth Client ID」。
  5. 不要把 Web client ID 寫進 manifest.json；Edge 會把自訂 manifest key 標成 Unrecognized manifest key。
  6. 不要動 oauth2.client_id；那個仍是 Chrome native auth 使用。

3. 重新載入 Edge extension 並驗收

  1. 回到 edge://extensions，重新載入翻翻吧；若剛剛只改設定頁欄位，通常不需要重新載入，但測 OAuth 前建議 reload 一次。
  2. 重新打開翻翻吧設定頁 >「雲端同步」。
  3. 狀態列應看到 Native Client：已設定、Web Auth Client：已設定、Redirect URL：...。
  4. 點「登入 Google」，選 TeaKingdom@gmail.com。
  5. 若測試階段看到未驗證 app 提醒，可繼續完成授權。
  6. 登入成功後，依序測「上傳目前設定」、「下載雲端設定」、「取消覆寫提示」。
  7. 測完把結果回填到本文件的 v1.7.3 Session Log / QA 矩陣。

4. 如果還是 redirect_uri_mismatch

檢查項目處理方式
OAuth 用戶端類型必須是 網頁應用程式（Web application）client，不是 Chrome 擴充功能 client。
Client ID 貼錯位置Web client ID 要貼到設定頁「Edge / Chromium Web Auth Client ID」欄位，不要覆蓋 oauth2.client_id。
重新導向無效：不得包含空格字元通常是貼到了 Redirect URL： 前綴或前後空白。欄位內只能有純 URL，例如 https://xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.chromiumapp.org/。
Redirect URL 不一致Google Cloud 的「已授權的重新導向 URI」必須和設定頁狀態列的純 URL 一字不差，包含最後的 /。
Extension ID 改變重新載入或換安裝方式後，若 Redirect URL 改變，要把新的 URL 加回 Google Cloud。
Project 不一致確認 Web client 建在翻翻吧目前使用的同一個 Google Cloud project。
測試使用者未加入如果 app 還在「測試中」（Testing），確認登入帳號 TeaKingdom@gmail.com 已在「測試使用者」（Test users）。
