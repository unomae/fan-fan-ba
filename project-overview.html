翻翻吧專案總覽與 Roadmap

這份文件整理目前 Chrome / Edge extension 的架構、設定、功能狀態、測試方式、roadmap 與可清理候選。目標是讓之後每次更新都有一個固定的專案記憶入口。

現況

產品定位

選取網頁文字後提供翻譯、解釋、優化改寫，也提供右側常駐浮球作為全文翻譯、最近查詢、單字本、暫停網站與設定入口。

主要 Provider

模型 registry 集中在 models.js，支援 Groq、Gemini、OpenRouter。預設模型為 Groq 的 Llama 4 Scout。

目前重點

浮球 UI 已加入設定入口與一致間距；全文翻譯 Beta 正在補強短標題、重複段落與可見區域收集穩定性。

最新進展

2026-05-28 修正全文翻譯短標題誤走字典 JSON、父子節點重複翻譯，以及浮球停用 icon 位置與 tooltip 文案。

架構流程

選字工具流程

  1. content/main.js 偵測 selection。
  2. content/toolbar.js 顯示翻譯/解釋/優化工具列。
  3. content/main.js 透過 message 或 port 呼叫 background.js。
  4. background.js 依模型 provider 呼叫 Groq/Gemini/OpenRouter。
  5. content/result-card.js 顯示字典卡、段落結果、Obsidian 與收藏操作。

浮球與全文翻譯流程

  1. content/floating-ball.js 建立右側吸附浮球。
  2. 浮球可開收藏/紀錄、全文翻譯、設定，並提供「在此網站停用」。
  3. content/page-translator.js 收集可見段落並逐段翻譯。
  4. 全文翻譯請求帶 pageTranslation: true，短標題不走單字字典 prompt。
  5. 可見段落收集會避開已翻譯元素、父子節點重複與相同文字重複。
  6. 翻譯狀態面板提供雙語/譯文/原文與密度切換。
  7. 全文模型由設定頁 pageTranslationModel 管理。

技術守則

  • Content UI 不污染宿主頁。
  • API Key 只保存在 Chrome storage。
  • 模型與語言設定集中在 registry。
  • 全文翻譯先做可見段落，避免全頁 DOM 破壞。
  • 可重建產物不要混進必要架構。
